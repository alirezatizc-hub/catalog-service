# Torob Assistant v2
اجرا: `npm start` → http://localhost:3000 | تست: `npm test` (Node ≥ 18، بدون وابستگی)

## ساختار
- `src/data/schema.js` نگاشت ستون‌ها (CONFIRMED = طبق گزارش ChatGPT از ساختار دیتاست؛ SHOP_CANDIDATES و SPEC_ALIASES = حدس‌های قابل تنظیم) · `src/data/loader.js` CSV/JSON → اعتبارسنجی → join با شناسه → استخراج specs → ثبت فیلترهای پویا → گزارش
- `src/engine.js` جست‌وجو/فیلتر/فاصله/ساعت کاری · `src/demo.js` نمونه‌ی Demo در شکل دیتاست · `src/tools.js` قرارداد ابزارهای AI · `server.js` API (`/api/report` گزارش نگاشت)
- `public/` رابط (بدون تغییر منطق؛ فیلترها از `/api/meta` می‌آیند) · `test/` تست‌ها با `fixtures.js` (نمونه‌ی آزمایشی، نه داده‌ی ترب)

## وضعیت
**پیاده و تست‌شده روی نمونه‌ی آزمایشی (۲۳ تست):** نگاشت ستون‌های شناخته‌شده products/offers، نگاشت قابل تنظیم shops با گزارش مفقود/ناشناخته، join با product_id/shop_id، استخراج رنگ/رم/حافظه/سایر مشخصات از specs، فیلتر پویا برای هر دسته، مدیریت مقدار خالی/قیمت و مختصات نامعتبر/JSON خراب/ارقام فارسی، فیلتر AND، ساعات کاری، جایگزین، مقایسه.
**هنوز تأییدنشده:** نام ستون‌های shops، کلیدهای واقعی specs (aliasها حدسی‌اند)، قالب ساعات کاری، گارانتی/اقساط روی داده واقعی؛ عملکرد روی ۲۲۶ هزار محصول.
**آماده‌ی اتصال (متصل نیست):** دیتاست واقعی، API هوش مصنوعی (`/api/chat` → ۵۰۳ بدون `LLM_API_KEY`)، نقشه/مسیریابی، کانال پیام به فروشنده، لیارا.
مرورگر هرگز کل دیتاست را نمی‌گیرد.

## چک‌لیست استقرار Liara (انجام نشده)
1. `data/*.csv` را اضافه و `COLS` را تطبیق دهید؛ 2. پلتفرم Node یا Docker (فایل‌ها آماده)؛ 3. متغیرها: `PORT` ، `LLM_API_KEY` (فقط روی سرور)؛ 4. دیسک/اندازه‌ی RAM را برای دیتاست بسنجید؛ 5. `/api/health` را بررسی کنید؛ 6. تست نهایی روی URL عمومی.

## سناریوی دمو ۵ دقیقه‌ای
۱) بنر «داده نمونه» و معرفی مسئله (۰:۴۰) ۲) «گوشی» → سامسونگ → آبی → مدل → رم → حافظه؛ نشان‌دادن حذف یک فیلتر از نوار بالا (۱:۴۰) ۳) مقایسه قیمت، انتخاب ۳ فروشگاه برای جدول مقایسه، بودجه (۱:۰۰) ۴) نقشه: کشیدن موقعیت، تغییر شعاع، توضیح «فاصله مستقیم» (۰:۴۰) ۵) فیلتر «فقط بازها»، فروشگاه ساعت نامشخص و جایگزین (۰:۴۰) ۶) شفافیت: قیمت قدیمی، موجودی تأییدنشده، وضعیت «ارسال نشده» پرسش (۰:۴۰) ۷) معماری آماده‌ی دیتا/AI/لیارا (۰:۲۰)

## قرارداد mapping.json (تست‌شده)
- `SHOPS.<فیلد>` = نام ستون (رشته یا آرایه)؛ **جایگزین** نامزدهای پیش‌فرض می‌شود، نه اضافه؛ بدون حساسیت به حروف و فاصله‌ی ابتدا/انتها.
- ستون override ناموجود ← fallback ندارد، در `report.tables.shops.overrideMisses` و `report.warnings` می‌آید.
- کلید/فیلد ناشناخته، نوع اشتباه یا یک ستون برای چند فیلد ← `report.warnings`. mapping.json خراب ← `report.ok=false` بدون استثنا.
- `SHOPS.id` ، `CONFIRMED.<جدول>.<فیلد>` و `SPEC_ALIASES` هم قابل بازنویسی‌اند.

## ایندکس و بنچمارک
`npm test` (مقایسه‌ی ایندکس با روش قبلی روی داده‌ی مصنوعی) · `npm run bench` (آزمایشی، مصنوعی هم‌اندازه با دیتاست گزارش‌شده؛ روی داده‌ی واقعی تکرار شود).

## تست مرورگر (Playwright + Chromium) — `npm run test:e2e`
۵۴ بررسی (هر کدام فقط با `True` واقعی پاس می‌شود) روی مجموعه‌ی آزمایشی کوچک و کنترل‌شده (`test/e2e/e2e.py`، شامل متن‌های HTML مخرب؛ نه داده‌ی ترب): جریان انتخاب، بودجه، مقایسه، مرتب‌سازی، ساعت کاری، جایگزین، رد مجوز مکان‌یابی، خطای API و تلاش مجدد، اطلاعات ناقص، XSS، موبایل (۳۷۵px)، فوکوس کیبورد و کنتراست (روشن/تیره). بخشی از `npm test` نیست (نیاز به Playwright برای Python).

## قرارداد ابزارهای ایجنت
`GET /api/tools` فهرست ابزارها · `POST /api/tools` با بدنه‌ی `{name,args}` (اعتبارسنجی نوع/الزامی/enum/پارامتر ناشناخته). `next_question` بعدی‌ترین مشخصه‌ی نامعلوم و گزینه‌های واقعی را می‌دهد و `ask_clarification` سؤال تکمیلی را برمی‌گرداند. هنوز به هیچ مدلی وصل نیست.

## آماده‌ی اتصال بعدی (متصل نیست)
نقشه: `/api/meta` → `mapProvider:null, routing:null`؛ رابط فقط نقشه‌ی طرح‌وار و «فاصله‌ی خط مستقیم» نشان می‌دهد. LLM: `/api/chat` → ۵۰۳ بدون `LLM_API_KEY`. ارتباط با فروشنده: وضعیت `not_sent`.

`npm run test:mutations`: ۸ جهش عمدی در یک کپی از پروژه (مثلاً غیرفعال‌کردن Enter روی کارت، جابه‌جایی وضعیت ساعت کاری، حذف escape) اجرا می‌کند و انتظار دارد e2e شکست بخورد؛ هر ۸ جهش شناسایی شد.
