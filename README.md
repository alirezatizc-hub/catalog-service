# ترب‌یار — دستیار خرید حضوری

کمک می‌کند قبل از راه افتادن در تهران بدانی **کدام فروشگاه واقعاً این محصول را دارد، چقدر است، باز است یا نه، و چطور برسی**.
همه‌ی اعداد از دیتاست ترب خوانده می‌شوند؛ هیچ داده‌ی نمونه‌ای در رابط نمایش داده نمی‌شود و هیچ چیز تأییدنشده‌ای به‌عنوان واقعیت جا زده نمی‌شود.

- اجرا: `npm install && npm start` → `http://localhost:3000`
- تست: `npm test` (۹۸ تست، بدون نیاز به دیتابیس/مرورگر)
- دیتابیس: PostgreSQL روی لیارا (متغیرهای محیطی در پنل تنظیم شده‌اند)

## چه کاری می‌کند؟

| قابلیت | توضیح صادقانه |
|---|---|
| انتخاب محصول با چند سؤال | دسته → برند → رنگ/رم/حافظه… یا یک جمله فارسی؛ گزینه‌ها از داده‌ی واقعی همان مسیر می‌آیند، نه فهرست ثابت |
| مقایسه‌ی فروشگاه‌ها | قیمت ثبت‌شده، فاصله‌ی خط مستقیم، وضعیت باز/بسته در همین لحظه، زمان ثبت قیمت، گارانتی، اقساط (اعلام‌شده و حضوری)، ترب‌پی، ارسال فوری |
| تصمیم‌یار «الان کجا بروم؟» | حکم `برو / دورتر ولی باز / همه بسته‌اند / چیزی ثبت نشده` + نزدیک‌ترین گزینه‌ی باز، گزینه‌های دورترِ باز، و صریح‌ترین جمله‌ی ممکن درباره‌ی چیزی که نمی‌دانیم |
| پاساژهای نزدیک | خوشه‌بندی فروشگاه‌ها بر اساس «پاساژ/بازار» نوشته‌شده در آدرس + فاصله (`/api/hubs`) |
| «هم‌دسته‌ها» | فروشگاه‌هایی که همین دسته را دارند ولی این محصول را در ترب ثبت نکرده‌اند؛ با برچسب «ممکن است»، نه «موجود» |
| برنامه‌ی مراجعه | انتخاب تا ۳ فروشگاه → ترتیب نزدیک‌ترین‌همسایه + این‌که در لحظه‌ی رسیدن بازند یا نه (`/api/trip`) |
| زیر نظر گرفتن قیمت | قیمت هدف و شعاع؛ وقتی بهترین قیمت به هدف برسد یا وضعیت عوض شود علامت می‌خورد |
| پرسش از فروشنده | متن آماده‌ی واتساپ/تماس/کپی + پیگیری وضعیت پرسش (هیچ پاسخ جعلی ساخته نمی‌شود) |
| «بگذار ما تماس بگیریم» | ثبت درخواست با رضایت صریح، در ساعات کاری ۰۹:۰۰–۲۱:۰۰ تهران، با سقف روزانه و `earliest` واقعی؛ بدون وب‌هوک، فقط صف می‌شود |
| نقشه | Leaflet محلی + کاشی از `/api/meta`؛ مسیریابی واقعی فقط اگر کلید نشان تنظیم شود، وگرنه «خط مستقیم» با همان برچسب |

## ساختار

```
server.js                API + فایل‌های استاتیک (gzip، CSP، محدودیت نرخ، محافظت از path traversal)
src/db.js                اتصال PostgreSQL لیارا، مهاجرت، خواندن جدول‌های دیتاست، استور پرسش/تماس/هشدار
src/import-pg.js         ایمپورت CSV/JSON به PostgreSQL (یک‌بار)
src/data/schema.js       نگاشت ستون‌ها و نام‌های جایگزین هر جدول
src/data/loader.js       CSV/JSON → اعتبارسنجی → join → specs → ایندکس‌های فیلتر → گزارش کیفیت
src/engine.js            Index، جست‌وجو/فیلتر/فاصله، ساعت کاری (Asia/Tehran، شیفت شبانه)، اعتبار اقساط حضوری
src/advice.js            advise()، hubsOf()، maybeShops()، planTrip()، تخمین زمان رسیدن
src/tools.js             ۱۱ ابزار قراردادی برای ایجنت (`GET/POST /api/tools`)
src/geo.js               تنظیم کاشی و مسیریابی اختیاری (نشان)
src/llm.js + src/nlu.js  فهم جمله (اختیاری؛ بدون کلید، قاعده‌محور کار می‌کند)
public/                  رابط RTL (وزیرمتن و Leaflet محلی، بدون CDN): app.js، map.js، app.css
test/                    ۹۸ تست: نگاشت/لودر/موتور/ابزارها/سرور + دیتاست واقعی‌شکل + API + اتصال رابط
```

## دیتاست

حجم مرجع: **۲۲۵٬۹۰۳ محصول · ۶٬۴۷۶ فروشگاه · ۳۳۱٬۵۰۶ آفِر**.

ستون‌های شناخته‌شده (نام‌های دیگر از طریق `src/data/schema.js` و `data/mapping.json` پذیرفته می‌شوند):

- `products.csv`: `product_id, persian_title, brand_name, category_name, model, specs, image_urls`
- `shops.csv`: `shop_id, name, address, category_names, contacts, instagram, lat, location_label, lon, payment_options, supports_fast_delivery, website_url, weekly_hours`
- `offers.csv`: `offer_id, product_id, shop_id, price_toman, last_price_changed_at, seller_title, description, warranty`

نکته‌های کیفیت داده که در کد رعایت شده‌اند:

- `model` برای ۲۲۱٬۸۴۷ محصول خالی است → هرگز بر آن فیلتر نمی‌کنیم؛ عنوان `persian_title` مبنا است.
- قیمت خالی/غیرعددی/≤۰/≥۱۰۰ میلیارد جدا شمرده می‌شود؛ `1` و قیمت‌های تکراری‌رقم «جانگهدارنده» تشخیص داده می‌شوند و به‌عنوان ارزان‌ترین پیشنهاد نمی‌آیند.
- `weekly_hours` فقط برای ۴٬۴۷۳ فروشگاه هست؛ بقیه «ساعت نامشخص» می‌مانند. `00:00–00:00` جای‌خالی است، نه ۲۴ ساعته. شیفت شبانه (مثل `22:00–02:00` و `22:00–26:00`) پشتیبانی می‌شود.
- «اقساط» دو معنی دارد: `installment` در سطح فروشگاه و اعتبار ارائه‌دهنده در سطح آفِر (`min/max` مبلغ و دسته). این دو با هم قاطی نمی‌شوند (`inst` و `credit` در API).
- موجودی در دیتاست نیست → همه‌جا «تأییدنشده» است تا وقتی کاربر/فروشنده چیزی ثبت کند.

جزئیات بیشتر و روش ایمپورت: [`data/README.md`](data/README.md).

## متغیرهای محیطی

| کاربرد | نام‌ها |
|---|---|
| PostgreSQL | `DATABASE_URL` **یا** `PG_URI` (روش مستندات لیارا)، یا `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE`، یا `DB_*`/`POSTGRES_*`؛ `PGSSLMODE=require` در صورت نیاز |
| جدول‌ها | `PG_TABLE_PREFIX` (پیش‌فرض خالی؛ جدول‌های دیتاست `products/offers/shops`)، `PG_POOL_MAX`، `PG_CONNECT_TIMEOUT_MS`، `PG_STATEMENT_TIMEOUT_MS` |
| اجرا | `PORT` (پیش‌فرض ۳۰۰۰؛ روی `0.0.0.0` گوش می‌دهد)، `DATA_DIR` (فایل‌های جایگزین محلی)، `ETA_MODE=walk\|drive` |
| تماس | `CALL_WEBHOOK_URL`، `CALL_WEBHOOK_TOKEN` (اختیاری؛ بدون آن درخواست‌ها فقط در صف می‌مانند) |
| مسیریابی | `NESHAN_SERVICE_KEY` (اختیاری)، `NESHAN_DIRECTION_URL`، `MAP_TILE_URL`، `MAP_TILE_ATTRIBUTION`، `MAP_MAX_ZOOM` |
| AI (اختیاری) | `BOXAPI_API_KEY` یا `LLM_API_KEY`، `BOXAPI_BASE_URL`، `AI_MODEL`، `LLM_TIMEOUT_MS` |

هیچ مقدار حساسی در لاگ چاپ نمی‌شود؛ `/api/status` فقط **نام** متغیرهای موجود را نشان می‌دهد.

## استقرار روی لیارا

1. **دیتابیس**: یک PostgreSQL در لیارا بسازید و URI اتصال را در متغیر محیطی اپ بگذارید (`PG_URI` یا `DATABASE_URL`).
2. **اپ**: پلتفرم Node، نسخه ۲۰. `liara.json` آماده است (`npm start` اجرا می‌شود؛ پورت ۳۰۰۰).
3. **دیتاست**: یک‌بار از ماشینی که به دیتابیس دسترسی دارد:
   ```bash
   DATABASE_URL='postgresql://…' npm run import:pg -- /path/to/dataset
   ```
   یا `npm run import:pg -- --dry` برای بررسی فایل‌ها بدون نوشتن.
4. **استقرار**:
   ```bash
   npm i -g @liara/cli
   liara deploy --app torob-assistant --platform node
   ```
   (مسیر Docker هم آماده است: `liara deploy --platform docker`.)
5. **بررسی**:
   - `GET /api/health` → `{ok:true}`
   - `GET /api/meta` → `{ready:true, source:"postgres", counts:{...}}`
   - `GET /api/status` → وضعیت اتصال، جدول‌های پیدا‌شده، نگاشت ستون‌ها، `memoryMb`

سرور در استارت مهاجرت جدول‌های `inquiries/calls/watches` را انجام می‌دهد (Liara هوک مهاجرت ندارد). اگر دیتابیس در دسترس نباشد، اپ بالا می‌آید ولی با `ready:false` و پیام روشن در `/api/status` و رابط، نه با داده‌ی ساختگی.

## API

| مسیر | خروجی |
|---|---|
| `GET /api/meta` | آمادگی، منبع، شمارش‌ها، دسته‌ها و مراحل فیلتر، تنظیمات نقشه، `features` |
| `GET /api/status` | اتصال DB، جدول‌ها، نگاشت ستون‌ها، حافظه، خطاها |
| `GET /api/options?cat&key&...` | گزینه‌های واقعی یک مرحله با شمارش |
| `GET /api/offers?pid&lat&lng&rad&inst&credit&open&tp&ex&sort&min&max` | آفِرها + `insight` + `range` + `etaMin` |
| `GET /api/advice?pid&lat&lng&rad&max` | `verdict`، `openNow`، `farther`، `closedNearby`، `maybeShops`، `hubs`، `honesty` |
| `GET /api/hubs?lat&lng&rad&cat` | پاساژهای نزدیک با تعداد فروشگاه و نمونه‌ها |
| `GET /api/trip?pid&shops=s1,s3&lat&lng` | ترتیب مراجعه، کیلومتر/دقیقه‌ی هر ایستگاه، «می‌رسی/بسته» |
| `POST /api/watch` · `GET /api/watches` · `DELETE /api/watch` | هشدار قیمت/فروشگاه با وضعیت فعلی بازار |
| `POST /api/call` · `POST /api/call/update` · `GET /api/calls` | درخواست تماس با رضایت و `earliest` واقعی؛ به‌روزرسانی فقط توسط همان client |
| `POST /api/inquiry` · `POST /api/inquiry/update` · `GET /api/inquiries` | پرسش از فروشنده و پیگیری (بدون پاسخ ساختگی: `not_sent`) |
| `GET /api/tools` · `POST /api/tools` | ۱۱ ابزار قراردادی برای ایجنت |
| `POST /api/chat` | فهم جمله با مدل (بدون کلید → ۵۰۳؛ قواعد محلی جایگزین است) |

## تست‌ها

```
npm test    # ۹۸ تست
```

- `test/loader|mapping|sort|engine|hours|index|tools|server` — منطق داده، فیلترها، ساعت کاری، قرارداد ابزارها (فیکسچر کوچک `test/fixture-mini.js`)
- `test/dataset.test.js` — با **شکل دقیق ستون‌های دیتاست چالش** (`test/real-fixture.js`): نگاشت، ارقام فارسی، JSON خراب، قیمت جانگهدارنده، شیفت شبانه، اقساط حضوری، ترتیب مسیر
- `test/api.test.js` — ۱۱ سناریوی HTTP روی `createServer` (مشاوره، پاساژ، مسیر، هشدار، تماس با رضایت و پنجره‌ی تهران، پرسش، فیلتر `credit`، استاتیک و path traversal، و بالا ماندن اپ بدون دیتاست با `ready:false`)
- `test/ui.test.js` — اتصال ایستای رابط: مسیرهای `/api` که صفحه صدا می‌زند در سرور هستند، آیکن‌ها تعریف شده‌اند، `map.js` واقعاً وجود دارد و از `meta` کاشی می‌گیرد، و هیچ بنر/داده‌ی نمونه‌ای در رابط نیست

## محدودیت‌های صادقانه

- **موجودی** در دیتاست نیست → همه‌جا «تأییدنشده».
- **ساعت کاری** فقط برای ۴٬۴۷۳ فروشگاه ثبت شده؛ بقیه «نامشخص» می‌مانند و در توصیه هم همین‌طور گفته می‌شود.
- **اقساط حضوری** فقط برای ۸۲ فروشگاه قابل اثبات است؛ بقیه «ندارد/نامشخص» است، نه «دارد».
- **فاصله و زمان** خط مستقیم × ضریب خیابان است، مگر کلید مسیریابی تنظیم شود؛ برچسب همین را می‌گوید.
- **تماس خودکار** پیاده نشده: بدون `CALL_WEBHOOK_URL` فقط صف می‌شود و هیچ پیامی به فروشگاه نمی‌رود.
- **هشدار** بر اساس داده‌ی لحظه‌ی درخواست ارزیابی می‌شود (بدون کرون/پوش‌برودکست)؛ وضعیت در «پیگیری‌ها» دیده می‌شود.
